#### Вопрос 1

В `BaseTest` используется `implicitlyWait(10s)`. Ваш коллега добавил явный `WebDriverWait(driver, 15s)` в одном из тестов. При запуске тесты стали нестабильными - иногда падают, иногда нет, без видимой причины. Объясните возможную механику происходящего и как бы вы исправили проблему.

#### Ответ:

Я предложил бы использовать в тестах явные ожидания и убрать неявное ожидание 10 секунд, поскольку они могут накладываться друг на друга и получается так, что ожидание элемента, который должен появиться например через 12 секунд приведет к выбрасыванию исключения т.к. есть неявное ожидание в 10 секунд, что не очень удобно.

#### Вопрос 2

Тест-сьют из 200 UI тестов стабильно проходит локально, но в CI падает ~15% тестов с разными ошибками: `StaleElementReferenceException`, `NoSuchElementException`, и иногда - неожиданный `401` от API. Тесты перезапускаются и проходят. Какие 3 наиболее вероятные причины нестабильности вы бы проверили в первую очередь, и как бы вы их диагностировали?

#### Ответ:

1. Исключения могут выбрасываться в случае, если времени ожидания не хватает при запуске в CI. Можно попробовать увеличить время для ожиданий и перезапустить несколько раз тесты, проверить изменения.
2. Возможно ресурсов сервера не хватает (особенно актуально при параллельном запуске UI-тестов). Это может приводить к флакающим тестам. Можно проверить потребление ресурсов сервера во время выполнения, и если ресурсов не хватает, то можно попробовать уменьшить количество квот для одновременно запускаемых браузеров и попробвать выполнить тесты повторно.
3. Ошибка 401 может быть связана с тем, что используются невалидные данные для авторизации. В первую очередь посмотрел бы логи запроса/ответа. Еще причиной может быть, что несколько тестов использовали одну сессию, которая удалялась в одном из тестов и приводила к 401 ошибке в другом тесте. Также проверить, прошла ли успешно авторизация на предыдущих шагах, возможно авторизация не выполнилась, а тест пошел дальше.

#### Вопрос 3

Ниже приведен полный код теста (импорты опущены для краткости). Найдите в нем проблему и объясните её:


```java
public class TestDeleteUser {
	@Test
	void testDeleteUser() {
	    String userId = "user-123";
	    apiClient.deleteUser(userId);
	
	    Response response = apiClient.getUserById(userId);
	    assertThat(response.statusCode()).isEqualTo(404);
	}
}
```

#### Ответ:

В тесте отсутствуют шаги по созданию пользователя. Неизвестно когда создается пользователь с id "user-123". Для стабильного теста необходимо в тесте создать пользователя, таким образом будет известен его id, после чего удалить по этому id. В целом хардкод id в тестах не самая лучшая практика, лучше использовать генерацию данных. По лучшим практикам название класса должно было быть DeleteUserTest, а метода deleteUserTest.
